# Agentic timeline fact search

## Objective
Replace single-pass keyword retrieval plus tool-free synthesis with one bounded read-only research agent that analyzes a question, searches active timeline facts multiple times, fetches details/source-entry context and returns a grounded answer with distinct fact/context citations.

## Authorization and baseline
- User explicitly approved iterative search and source-entry recovery as separately cited context; this is NOT authorization to create/edit/accept facts or search arbitrary raw entries.
- Branch feat/agentic-fact-search starts from current6a6b697 with pre-existing uncommitted native telemetry integration carried forward. Preserve all native/HTTP/cost/SearchFacts fixes, user config, assets and unrelated dirty/untracked files. No commits/push/PR without explicit request.
- Exploration baseline (replaced by this feature): SearchEntriesAgent was one-pass, called no model if lexical hits were empty, and registered tools=[]. Retrieval matched any of12terms and ordered by newest entry, not relevance.

## Product contract
- Stay within authenticated project/timeline. Every tool and final validation rechecks active user/project permission, timeline ownership, fact revision and effective eligibility; pending/invalid/foreign facts remain excluded.
- One research agent, read-only tools: search_facts, fetch_facts, fetch_source_entry. Search and reformulate even if original lexical query finds nothing, provided effective facts exist. No tool-free speculative answer or original-entry fallback without fact anchors.
- Facts are primary evidence; source-entry text is separate context, never silently promoted to an active/accepted fact. Final narrative must distinguish sources and include server-validated citations.
- No immutable historical source content store was found. Fetch current entry only by an active fact ID actually retrieved in this operation; verify its source fingerprint still matches before exposing content and before final answer. On mismatch/revocation/revision change withhold/refuse stale context. Clarification evidence is not automatically entry text.
- Search across eligible facts using bounded targeted queries, deterministic relevance ranking over recency, deduplication and a server-owned evidence ledger. The model may cite only IDs actually returned by tools; final citations are mapped server-side, never trusted model-supplied provenance.
- Initial safe operation limits: <=6 actual model/provider calls, <=8 tool invocations (<=4 search queries), <=40 distinct facts, <=10 hits/search, <=3 entry contexts, <=4000 characters/context, <=12000 source-context characters and <=32000 total serialized tool-evidence characters, <=1500 output tokens/model call, <=60seconds operation deadline. These are bounds, not new market-price assumptions. Context is character-bounded; do not claim exact input-token ceilings without a tokenizer.
- Enforce provider-call limits before requests, with SDK retries disabled for this bounded path; tool limits alone cannot stop model continuations. Use supported installed SDK iteration bounds where applicable, verify rather than guess APIs. Cancellation reaches tools/provider; no hidden retry loops.
- Budget exhaustion/insufficient evidence must be explicit and preserve safe available evidence without an ungrounded answer. No silent completeness claim. If no effective facts exist, return an explicit empty result without needless model calls.
- Keep native agent/chat/tool traces and existing privacy boundary. No prompts/question text/source content/tool args/results in OTLP. No real provider calls, Logfire exports, host restart or DB migration during implementation/verification.

## Acceptance criteria
- A question can lead to several differently phrased searches and evidence expansion; initial zero hits do not preclude reformulation.
- Real SDK tools execute under existing native telemetry; fake model scripts prove multi-turn flow, without paid requests or fabricated post-hoc tool spans.
- No cross-scope/inactive/unseen fact-to-entry access; malicious evidence/instructions cannot grant permission or create provenance. Context fingerprint/current eligibility validated; stale context not returned as current source.
- Fact citations and source-context citations are distinguishable in API/UI, validated against ledger and correct entry/provenance; malformed/invented/mixed citations cannot make narrative appear grounded.
- Actual provider/tool/context/output/deadline limits and cancellation are deterministic in tests; no extra SDK retries/double-counted usage. Use one operation cost scope if required for usage budget, but missing prices stay unknown and no fake cost estimate is introduced.
- Existing native telemetry/privacy/cost/legacy source provenance and offline app behavior pass. API+UI must both be complete before claiming user-facing delivery.
