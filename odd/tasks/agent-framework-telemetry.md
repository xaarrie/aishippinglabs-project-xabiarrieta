# Agent framework telemetry to Logfire

## Objective
Instrument the common agent framework once, track actual tokens and configurable estimated costs per explicit multi-agent operation session, and export safe traces/session summaries from the Web API to Logfire over OTLP. Keep agent code backend-neutral and preserve existing execution semantics.

## Scope and decisions
- Trace all LocalCustomAgent run overloads and LocalCustomHarnessAgent runs, including structured validation, errors and cancellation.
- Prefer compatible built-in Microsoft Agent Framework instrumentation at the shared factories for nested agent/chat/tool execution when it can preserve the no-sensitive-content policy; do not fabricate tool execution spans from completed messages.
- Use stable source names, ambient parent propagation and safe metadata. Never capture prompts, responses, instructions, tool arguments/results, credentials, or exception messages/stack traces that can contain payloads.
- Host owns SDK lifetime, sampling/export configuration and Logfire authentication. Use OTLP HTTP/protobuf, region-specific Logfire endpoints and an external write token. Export is opt-in and absent configuration must not send to localhost or break existing hosts.
- Initial increment is tracing; metrics, log export, embeddings, streaming API additions and business-agent refactors are out of scope. User subsequently requested framework-level per-session cost tracking based on tokens; user selected an explicit operation scope shared across agents, in-memory lifetime and final Logfire summary. Prices are externally supplied per model; unknown usage/prices must not masquerade as zero cost. No persistence.
- User selected Logfire. Preserve all unrelated dirty/untracked changes. No commits, push or PR without explicit user request.

## Acceptance criteria
- Agents get tracing centrally without per-agent edits; end-to-end framework spans include validation and outcome.
- Traces preserve ambient request/nested parentage and normal return/exception/cancellation behavior.
- No sensitive content in custom telemetry; native SDK nested spans are enabled only if privacy can be guaranteed under supported configuration.
- Logfire endpoint, auth and service name are external configuration; no real tokens in source, docs, tests or output.
- Missing Logfire configuration leaves startup and agent behavior unchanged. Test exporter wiring locally without sending data externally.
- Cost tracking aggregates each actual provider response exactly once across agents/tool iterations under a caller-created operation session; no AgentResponse plus ChatResponse double counting. Decimal estimates use external per-model rates in one currency. Input/output/cache/reasoning subsets must not be double charged; unknown usage/pricing stays explicit.
- Cost scope works without telemetry listeners/exporters, preserves async isolation and nested scope restoration, and has a final safe session summary when tracing is enabled. Await session work before disposal; no restart persistence promised.
- Applicable focused tests and build pass; real Logfire delivery needs user credentials and is reported as pending if unavailable.
