# Agent trace content

## Objective
Expose Microsoft Agent Framework native user/assistant messages and internal harness tool names, arguments, and results in OpenTelemetry by default, with an explicit opt-out.

## Context and decisions
Current native instrumentation emits operations but explicitly disables sensitive capture; the host sanitizer also removes payloads. The user's current request supersedes the earlier no-payload policy for this capability. Use a single immutable host setting `Logfire:CaptureAgentContent` (environment `Logfire__CaptureAgentContent`), default TRUE, consistently for factories and export. User explicitly requested default-on after the initial opt-in design; `Logfire__CaptureAgentContent=false` disables payload capture. Configured exports will include conversation/tool payloads even in production; exporter remains disabled without endpoint/token. No global mutable switches. Explain that enabled traces contain sensitive conversation/tool data; not hidden model reasoning unavailable from SDK.

## Scope and constraints
Cover plain and harness shared factories plus WebAPI fact extraction/review/search creation paths. Preserve cost accounting, bounded execution, existing raw-client identity, no duplicate native spans, and explicit-off privacy tests. Keep HTTP/credential filtering, safe error handling, fail-closed immutable events/links unless vetted SDK content requires a specifically tested change. Do not expose arbitrary exception text by opening the processor wholesale. Preserve all pre-existing dirty/untracked changes; no `.env`, credentials, launchSettings, unrelated sources, real paid calls, remote exports, process restarts, pushes or commits. Commits require explicit user request under the active safety contract.
