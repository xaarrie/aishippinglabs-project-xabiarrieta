# Information research: batched searches

## Contract

Production Search gives the model zero AI tools in both isolated stages: typed query planning (or an application refusal), then evidence-grounded structured synthesis. The server invokes `search_facts_batch(queries, limit = 10)` directly and, when facts were emitted, `FetchEmittedSourcesAsync()` once. The public/SDK wrappers `search_facts_batch` and `fetch_source_entry(entryIds)` remain available for compatibility, but are not registered with Search. The search accepts N expressions with no count ceiling, retaining per-expression validation (300 characters, first 12 distinct lexical terms), authorized lexical ranking, hit/fact bounds, deadline and global output limits. It returns `Results` grouped by original expression, `RemainingSearchQueries: null`, `Status` and `Truncated`. Facts expose `EntryId`, but not hidden author/fingerprint/review/job provenance.

A batch costs one tool invocation. Actual uncached attempts count, including invalid/read failures; equivalent lexical expressions reuse validated results within that batch. The effective hit limit is server-capped. Batch output is charged exactly once as the complete model projection, including escaping. Only actually emitted facts enter the citation ledger.

The server derives the complete entry-ID set from ALL committed emitted `facts.Values` inside the existing admission gate, in stable first-occurrence Distinct order, then reuses `SourceCoreAsync`. It never uses the sorted final ledger, database-wide facts or model-selected IDs. The compatibility wrapper still normalizes duplicate source entry IDs before validation; the cap applies to distinct IDs, not raw request length. Every emitted fact for each entry is a validated anchor, with at most one context per entry. Unknown, foreign or missing IDs fail before source lookup or partial ledger commitment. All entries are validated before admitting any bounded context prefix. There is no three-entry, 4k per-entry or 12k aggregate context cap; all contexts share the remaining 32k serialized evidence budget and 60-second operation deadline. `OmittedEntryIds`, context `Truncated` flags and aggregate `Truncated`/`Partial` status disclose clipping. Legacy response context limits derive from fact/global bounds, not separate context caps; `MaxSearchQueries` is nullable.

## Safe closure

The shared operation gate consumes each phase before execution (and before argument binding for compatibility SDK wrappers). One search and, with emitted facts, one aggregate fetch are enforced in code. Fatal errors remain sticky; malformed, repeated or out-of-order calls cannot earn retries. Final validation rejects missing phases even when citations look plausible. No eligible facts skips the agent. After a valid plan, zero emitted facts skips both fetch and synthesis and returns finally revalidated insufficient evidence.

Search clipping reserves the complete minimal omission response for the next fetch. All emitted anchors and sources, including omitted contexts, are checked before context admission and finally revalidated. Provider-call, output-token, evidence and deadline safeguards are unchanged. With `MaxModelCalls=1`, a completed valid plan and server retrieval may yield only finally revalidated evidence under `Partial / ProviderCallLimit`, with no model narrative or citations. No completed plan/ledger means no partial success.

Planning requires exactly `decision`, `queries`, `refusalReason`: `Search` needs valid nonempty queries and a null reason; `Refuse` needs empty queries and only `OutOfScope` or `UnsafeRequest`. The latter returns server-owned `Refused / SafeRefusal` with fixed text and empty evidence/citations, after final scope/revision/deadline checks. Native provider refusal and malformed output remain errors. Synthesis requires exactly `content`, `citedFactIds`, `citedContextEvidenceIds`, valid GUIDs and final citation membership/duplicate/count checks. Both explicit wire schemas set `strict: true`; the shared extractor/verifier maxItems transform does not cap Search queries. A request-local Search-only leaf validator rejects unexpected tool calls before SDK continuation, after usage accounting. Other agents retain their tool envelopes and behavior.
